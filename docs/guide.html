How the Track 4 agent works

The agent reads one unit's frozen documents and answers every entity row with a label or a number, a 90% interval, quoted evidence and up to three reasons. Code computes what the data can settle. The House model reads the documents, copies figures, forecasts the rest and writes the reasons. This page explains why it is built that way, what each part does, and then follows five practice units through real runs. It describes build c5, which adds the fixes of 8 Oct for units the practice set does not have; the platform figures are still c4's until c5 is uploaded.

What a unit asksThe contract the agent works to, scorer 5.2.2 (5.3.0 from 9 Oct and in the Final)

A unit is one prediction task: a table of entities (companies, Treasury maturities, futures markets, macro series), one target per row, and a corpus of documents dated on or before the unit's cutoff. The target is a label (classification), a number (regression) or a number the rows are ordered by (ranking). The agent runs once per unit in a container, with the House model as its only language model.

In: /input

task.json
The prompt, the target's name, type and labels, cutoff_date, resolution_date, and the entity table with its feature columns (prior_year_q_eps, start_yield_pct, latest_precutoff_estimate ...).
card.toml
Interval level (0.90 on every unit), scoring parameters such as interval_leg, and the 600 s time limit.
manifest.json
Each document's label: the entity_ids it is about, or shared. Citing another entity's document makes a claim false.
corpus/*.json
Documents with doc_date and text: SEC filings, FRED and ALFRED vintages, Treasury, CFTC, BLS data, FOMC statements. Prose and pipe tables.

Out: /output/answer.json

label
One of the unit's labels, classification only.
point_forecast
The number in the prompt's units. On a ranking unit, the metric the rows are ranked by (larger means larger).
interval
{level: 0.9, lo, hi} on every row, even when the unit does not score it.
claims
One or more spans {doc_id, span_start, span_end, claim} in documents the entity may cite, or in its own task row (doc_id: "task").
submitted_reasons
Up to 3 reasons for the unit: premise, mechanism, answer implication, citations, scope. Graded in the Final only.

How a unit is scored

Each unit gets a composite of a prediction leg and an interval leg, scaled down by false claims. Both legs compare the answer with the unit's private naive rule (carry-forward on regression units; undisclosed on the others).

composite = 0.7 · PQ + 0.3 · IQ (PQ alone when the unit has no interval leg) PQ regression = naive_MAE / (naive_MAE + MAE) PQ classification = accuracy, anchored: naive → 0.5, perfect → 1 PQ ranking = (Spearman + 1) / 2, anchored to max(naive, 0.5) IQ = min( naive_IS / (naive_IS + IS), max(0.5, PQ) ) IS per row = (hi − lo) + 20 · distance by which the truth falls outside [lo, hi] unit score = composite · (1 − F / (F + min(T, 3E))) F false claims, T true, E entities board = −0.27 + 1.27 · mean(unit scores) Final adds 0.25 · reasoning grade

A claim is false when it cites another entity's document, when a figure in it is not in the span it cites, when the span is longer than 8,000 characters, or when it says nothing. A unit that fails the schema, cites a post-cutoff document, crashes or times out scores 0 (−0.27 on the board). The House allows 25 requests per unit and 4,000 output tokens per request; the agent stops itself at 570 s of the 600 s limit.

The practice units are format exemplars. The Final's held-out set is larger, spans many families that have no published counterpart, and adds documents dated after the cutoff and documents with edited values (issue #17, docs/CATEGORIES.md).

Design principlesEach one is a rule the code follows, with the place it shows

1

Data first; the model where it measurably wins

When a unit's documents hold an entity's history as a dated table, code computes a forecast from it and backtests a small menu of standard methods on that history. The data's point replaces the model's only where it measured far better: the next revision of a macro estimate, and EPS growth from a copied latest level. Everywhere else the model gives the point and the data gives the interval around it.

Where: priors.combine. Evidence: switching the priors off costs 0.037 on the 10-unit mean; the model's own point beat a 50/50 blend by 0.002.

2

Every number is traceable

A submitted number either comes from a computation on named table rows, and cites the last row it used, or is the model's, written next to quotes that code places verbatim in the original text. A quote that cannot be found is not cited, and a claim's text is the passage's own words, so a paraphrase cannot slip in a figure the passage lacks.

Where: cite.place, cite.verbatim, Forecast.anchor. Result: 0 false claims in 30 local runs of c4.

3

The reasons explain the submitted answer

Code works out what it decides before the model is called and writes it on the entity's line as a decided forecast. The model then writes reasons for the number that is actually submitted, instead of for a number that code later overrides.

Where: priors.decided, prompt.entity_lines. Evidence: the model's block agreed with the submitted value 36/36 (macrorev), 23/24 (eps-growth), 12/12 (credit-event), against 19/36, 1/24, 10/12 before.

4

Simple code, documented choices

Every component has an ablation row: what the 10-unit score loses when it is switched off. Components whose effect was within run-to-run noise were removed: corrective turns on answer calls, asking again, a level guard, the blend weight, and the 2,133-line document segmentation stack. The code shrank by 44% and the score held.

Where: results.md, provenance.md.

5

Triggered by data shape, never by unit names

No code branches on a unit id or family slug. A component fires when the data has its shape, matched by whole words: a vintage table, a dated column named like the entity, a numeric prior_* base that names a level, a credit label set, a yield_change_bps target. A shape the practice units lack is handled rather than refused: documents too large for one call are fitted smaller, a series no method can read costs one entity its prior, not the unit.

Where: types.CHANGE, priors._column, extract.bases, signals.findings, moves.starts, plan.doc_caps.

6

There is always an answer

A valid answer is written before any model call; a unit that does not even load gets one built from task.json alone that still passes the schema. The hard deadline is the card's time limit less 30 s, the soft one 30 s earlier, and reasons are chosen at most 10 s past it. No unit makes more than 25 requests. Every row is coerced into a shape no gate refuses: a label in the vocabulary, a finite point, an ordered interval, at least one citation (its own task row when nothing else is citable).

Where: cli.run, cli.hard_deadline, pipeline.floor_answer, assemble, preflight.

7

Nothing learned from outcomes inside the image

Methods are chosen per run by backtests on the unit's own pre-cutoff history. The few fixed constants are stated with their source: the yield floor's two constants were fitted on 58 FOMC meetings that resolved before the units' cutoffs, and practice-unit outcomes informed design choices under the issue #24 ruling, disclosed in the provenance file.

Where: forecast.py, moves.py, ARTIFACT_PROVENANCE.md.

ComponentsWhat each part does, the constants it rests on, and what it was measured to be worth

Load and the embargo

corpus.py 152 · types.py 97
Job

Build the Unit: task id, prompt, target name, type and labels, cutoff and resolution dates, interval level, entities (id, name, features), documents (id, title, date, source, text, manifest label), and the task table as JSON for "task" citations.

Rule

A document whose doc_date is missing or later than the cutoff is never constructed. The stale-evidence trap of the Final (post-cutoff documents placed in the corpus) is closed before retrieval, prompting or citation can see it. With a manifest, a corpus file it does not declare is not loaded either: citing it would refuse the unit.

Labels

Each document is about its entity_ids, or is shared. A document the manifest does not label is treated as market-wide (render.owned).

Tolerances

Shapes the scorer accepts but no practice unit uses: a vocabulary given only as label_assertions; a document's text in spans, joined by a space as the scorer reads it; a null name; dates with a time part, cut to the day. A document's id is its file name, which is how the scorer resolves a citation. A corpus_ref that names nothing in the corpus (a mount path, ./corpus/) reads the whole corpus: which documents an entity may cite is the manifest's to say.

The view: plain text

render.py 116 · retrieve.py 89 · tokens.py 46
Job

Show each document as its original text in a <doc id="D3" title date source about> tag, where about is market or the entity ids.

Rules
  • As written. A table row dated after the cutoff is shown: in a document dated before the cutoff it is a calendar, a projection or a curve by contract month, known on the document's date. Only the computed history leaves such rows out (data.rows).
  • Fit by retrieval. A document over its cap (DOC_MAX, or a smaller one the plan sets) has its whitespace collapsed; if still too big, it is cut into windows of about 16,000 characters (or half its cap, when that is smaller, so a small cap still shows the best passage) ending at sentence ends, ranked by BM25 against a query built from the task, and the best windows that fit are shown in document order with [... 41,203 characters left out ...] markers.
  • Tokens counted exactly with the Nemotron tokenizer when it is available, else a calibrated estimate that undercounts in under 5% of cases.

WINDOW 262,144CONTEXT_SHARE 0.4PROMPT_RESERVE 8,192DOC_MAX 96,665 tokensWINDOW_CHARS 16,000

Head-and-tail truncation kept 0 of 9 going-concern passages in one issuer's 10-K; BM25 kept all 9. Replacing the old segmentation with plain text left all 57 priors unchanged on the 11 units, cut prompts 17 to 25% on table units, and raised the estimate from 0.646 to 0.659 over 30 runs. Tables as data

data.py 97
Job

Read every dated table row of the admitted documents as history. A table is a header line of cells followed by rows whose first cell is a date (2024-10 or 2024-10-22), separated by | or tabs. The header names each cell, lowercased; a Markdown row’s outer pipes are dropped. The embargo is the document’s date, so a row or release column dated after the cutoff in an admitted document is read like any other. Every value keeps the span of its row, so a computation can cite exactly the rows it used.

Views
  • series(doc, column): one column's numbers in date order.
  • vintages(doc): a vintage table, where columns are as_of_<release date>; per reference period, its estimate as published at each release.

The forecast menu

forecast.py 252
Job

Turn a series into a point and a 90% band, choosing among standard methods by a backtest on the series' own pre-cutoff history, with nothing fitted offline.

Forms
  • Next value (an auction's bid-to-cover after past auctions of its tenor). Menu: last value, mean of the last 3, mean of the last 6, mean of all, median of all. Each is backtested one step ahead from the 4th value on; the smallest mean absolute error wins; the band is the point plus that method's error quantiles.
  • Change (a target named as a change, growth or return, such as a yield's move to the resolution date). The horizon is counted in the series' own steps: business days for a daily series, else whole periods of its median gap; a monthly row stands for its month's last day. With 5 or more backtest origins, no change and drift compete at that horizon; otherwise no change, with the step volatility scaled by the square root of the horizon.
  • Revision (the next published estimate of a reference month). The latest estimate plus the median of past revisions over the same number of releases at the same age. Releases that moved the whole history at once (over 10 times the usual revision) are left out. The label is the direction of the point. A table with one release has no revision history: the point is the latest estimate.
Intervals

With at least 19 backtest errors (for 90%), their 5% and 95% quantiles. With fewer, the small-sample interval mean ± t(n−1) · s · √(1 + 1/n).

Constants
MIN_FIT 3MIN_ERRORS 5BENCHMARK 10×

Priors and the two rules

priors.py 202
Finding a series

From the data, in this order: a vintage table in the entity's own documents whose period appears in its row, with a release date after the cutoff (a revision); else a dated column named as the entity, by its name or a text value of its row such as a series id, in its own or the market-wide documents; else, in its own documents only, the one column whose name's words all appear in the target's name. No match, or a tie, gives no prior. An entity whose series a method cannot read gets none; the others keep theirs.

Change targets

A target is a change when its name has the whole word change, growth, return or returns (exchange_rate and return_on_equity are not). Its series is forecast as a change to the resolution date, in basis points when the target says so and the series is in percent: its column says so, or a percent field of the entity's row (start_yield_pct) holds a value of its size.

Rule 1: point

The model's point, unless the prior decides it (a revision, or growth from a copied level) or the model gave none.

Rule 2: band

The prior's band moved to the point and still covering the prior's own band. On a ranking unit, the band's width centred on the point. A prior with no band (growth) takes the model's interval shifted to the point and stretched to hold the model's point. On revision units the label is the side of the point relative to the latest estimate.

Citations

Every prior cites the last row it used (anchor); a growth prior also cites the quote its level was copied from.

Evidence

Without priors the mean drops 0.037: eps-growth −0.229 (MAE 8.4 → 21.9), macrorev −0.132 (accuracy 0.583 → 0.444), cotpos −0.013. The former 0.5 blend of model and prior points lost to the model's own point by 0.002 (fomc-2024 +0.016, cpicomp +0.013, auction −0.010), so it was replaced by rule 1.

Copies

extract.py 213
Job

Small model calls that copy figures and forecast nothing. The system text: "You copy figures from documents. You do not forecast, estimate or compute." Each reply line is id | value: … | period: … | quote: "…".

Latest level

For a growth target, the entities with a numeric prior_* base that names a level (not a rate, change or percent field) and no history prior. Code keeps a line only when the value is one of the quote's numbers and lies between a fifth and five times the base, the quote is found in the entity's own documents, the period does not end after those documents' date, and the value differs from the base. A whole table row copied at the base's column takes its first column, because filings print the latest period first. Growth is (level − base) / |base|, times 100 when the target's name says pct or percent.

Earlier level

For a yield-change target, the call shows only the sentences that state a figure for a date before the cutoff (no table lines) and asks for every earlier level with its date, or none. The oldest valid level per entity is kept.

Budget

Copy calls are planned at most 8 and take at most 12 requests with their corrections, leaving the answer calls at least 13; the planner fits documents smaller to stay within that. A copy reply that fails the checks is sent back once with the problems named; answer calls have no corrective turn.

Constants
RATIO 0.2 to 5COPY_CALLS 8COPY_REQUESTS 12
Evidence

Without the growth copy the mean drops 0.023, all of it on eps-growth (MAE 8.4 → 21.9, IS 95 → 265). The earlier-level copy read 6 of 6 yields correctly after it was limited to dated sentences.

Filing signals

signals.py 79
Job

For a unit whose labels are exactly credit_event and no_event, decide the label from the entity's own filings where they state it plainly.

Rules
  • Going concern. "substantial doubt about … ability to continue as a going concern", not negated by no, not or whether just before it, decides credit_event, even when management says its plans alleviate the doubt.
  • Investment grade. A credit-rating passage with a grade from Aaa to Baa3 or AAA to BBB−, and no rating passage with a speculative grade, decides no_event.

The decided label and its passage go on the entity's line before the call; after it, a probability on the wrong side of one half is mirrored with its interval.

Evidence

−0.011 on the mean without it; credit-event accuracy falls from 0.833 to 0.750. The model weighs these signals against losses and charges and calls them either way from run to run.

Yield floor

moves.py 57
Job

For a yield target in basis points (bps, bp or basis_points in its name), a least half-width for every interval: the largest move the documents state (from the copied earlier levels), scaled to the horizon by the square root of time.

Formula

half = max |level_cutoff − level_earlier| · 100 · √(horizon / span), with spans and horizon in business days; no floor when no earlier level is stated.

Constants

None. An earlier form added constants fitted on 58 past FOMC meetings (A 28 bps, K 1.05, horizons 27 to 63 weekdays). The organisers ruled that outcomes which may postdate a held-out task’s cutoff may not choose or calibrate anything, so the Final build keeps only the rule.

Why

The model writes about ±10 bps for a yield change whatever the documents say, and an instruction did not change that.

Evidence

−0.004 on the mean, −0.033 on fomc-2022 and −0.008 on fomc-2024 without it, replayed on 12 stored runs (IS 400 → 1,277 and 181 → 486). The fitted form scored the same estimate on both units: their interval legs are capped by the prediction leg.

Plan

plan.py 194
Job

Split the roster into the fewest answer calls. Entities that share a document of their own (one not every entity has) go in the same call. Each call's prompt holds the prompt text, the documents every entity shares and the batch's own documents, within 40% of the window.

Output budget

An entity plans on 460 reply tokens (a 160-token block and its own 300-token reason), a call on 2 shared reasons besides, within 85% of the 4,000-token cap: (3,400 − 600) / 460 = 6 entities per call at most.

Fitting

A group whose documents together exceed the budget (an entity with two large filings, a filing about two entities) gives its larger documents the largest shared cap at which the group fits (doc_caps). With a call limit (the requests left), every document is lowered to the largest cap at which the groups pack into that many calls (fewer). Each document's cap goes with its call to the render.

Prompt

prompt.py 181
System

A careful financial analyst; only the documents and the entity rows, no outside knowledge, and "where the documents differ from what you remember, the documents are right"; verbatim quotes; what the target means for this target type; what a good answer is (close forecasts, 90% intervals no wider than needed, exact claims, reasons that agree with the forecasts); the output format; a filled sample with illustrative entities, whose label lines show the shape only.

User

<documents>; <task> opening with the task's facts (the target and its type, each label's definition from label_assertions, the cutoff and resolution dates) and then the unit's own prompt; <entities> as lines id — name | key: value; … with | decided forecast: … where code decides; a closing line naming the entities in order.

Quote rule

"an exact copy of a passage (at least 8 words) or of a whole table row, in double quotes".

Reply format

Structured text: a <reasons> section of <reason> blocks (citation, premise, mechanism, implication, scope), then <forecasts> with one <entity id> block per entity (claim, label, point_forecast, int_lo, int_hi). Chosen on 4 Oct over provider JSON: equal quality in a head-to-head, fewer tokens.

Calls and samples

pipeline.py 355 · llm.py 322
Client

OpenAI-compatible chat completions, plain text in and out (ask_text). Temperature 0, top_p 0.95, seed from QFBENCH_SEED. On the House route, thinking is off (enable_thinking: false). Development runs the same model, Nemotron 3 Super, on OpenRouter.

Retries

Rate limits and server errors (429, 5xx) wait 5, 15, 30, 60 s, or the server's Retry-After. Connection failures are retried; after 3 unreachable calls in a row the House is taken as down and the unit is answered from what is in hand. No retry starts with under 60 s left.

Budget

25 requests per unit: the copies take at most 12, 2 are kept for the earlier-level copy, the answer calls take the rest. A run's starts and corrections draw on one budget under a lock, so concurrent calls cannot pass the cap.

Pool

Calls start as soon as they fit beside the ones in flight: at most 4 at once and 200,000 prompt tokens together; a larger call goes alone. No call starts with under 30 s to the soft deadline; calls still running at it are abandoned.

Samples

The answer calls are drawn 5 times when 5 × calls fits both 15 and the requests left, else 3 times, else once. One draw when every entity's point is decided.

Asking again

An entity no reply answers and that has no prior is asked once more, in calls of its own, within the budget and the clock. One with a prior takes the prior: asking again never fired in 30 practice runs, where five samples cover a missing block.

Reading and merging replies

reply.py 287
Parse

Line by line into reasons and entity blocks. It accepts a field written as an element (<premise>…</premise>), continuation lines, quotes with or without a trailing note, and numbers in e-notation. A block with a label and no number keeps its label and takes the floor's point.

Merge

Per entity across samples: the most common label; among those samples, the median sample's block (its point and claims); an interval from the lowest lo to the highest hi of those samples. Samples that disagree are uncertainty, and a 90% interval pays twenty times a miss against once its width.

Evidence

The spanning interval is worth 0.008 on the mean against the median sample's own interval (eps-yoy IS 1.28 → 5.06).

Citations and assembly

cite.py 195 · assemble.py 251
Placing a quote

Only in the documents the entity may cite (its own and the shared ones), in their original text. Matching folds case, quote marks, dashes, invisible characters and whitespace runs; table cells may also match with whitespace ignored. Whole quotes across all those documents are tried before openings (at least 40 characters), then the longest piece around "...". The longest opening is found by bisection over the quote's word ends, since an opening that is found means every shorter one is too. A key: value quote of the entity's own row becomes a citation of that key in the task table.

Claim text

The passage's own words, at most 600 characters, never the model's paraphrase.

Assembly
  • One row per roster entity, in roster order; task id and target type from the unit, never from the model.
  • A label is taken as written, else matched without case, quotes, markup or the difference between spaces, hyphens and underscores; else it becomes the neutral one (inline, flat, no_event …), logged.
  • A missing point takes the floor: no change for a change target, else the row's latest_* or last_* value of the target's quantity (sharing a word with the target's name), else the answered rows' median.
  • A row no reply answered takes the answered rows' median width and most common label, never a zero-width interval.
  • An inverted interval is swapped; a missing bound takes the point.
  • Duplicate claims, content-free claims (the scorer's own word lists) and spans over 8,000 characters are dropped.
  • A row left with no claim cites the passage the roster cited most within its scope, else its first figure-bearing passage of 20 to 600 characters, else a value of its own task row.
  • On a ranking unit, rank follows the points, largest first.
Evidence

Plain-text quoting exposed invented quotes the old line-id shortcut hid: rows with another day's values, revision sentences no document has (fomc-2024 8, macrorev 10 in 30 runs). They are now left uncited; every entity still had a real claim, and floor claims stayed at 5 in 30 runs.

Reasons

reply.selected
Job

Choose up to 3 of every call's reasons as submitted_reasons, using the grader's own checks from baselines/guardrails_example/citation_rail.py.

Rules
  • Ranked first: cited before uncited, then by how much of the roster the reason is about, then its place in its call, then call order.
  • Then checked one at a time in that order, only until 3 are kept: citations placed in the documents; [task] citations, citations found nowhere and citations the judge would not see or over 8,000 characters dropped; a deny-list hit or malformed reason refused; a reason citing a passage another call's chosen reason cites refused; the grader's reasons_judged run on the trial set (size caps, no duplicates).
  • Each grader check is given only the documents the reasons cite, and selection stops 10 s past the soft deadline.
Why

Leaving reasons out costs nothing, but a reasons block that fails the schema voids the whole unit. In the Final, reasons are graded against hidden target reasons for coverage, grounding, inferential link and consistency with the answer.

Evidence

Checking every reason first, each check reading the whole corpus, made assembly the slowest stage on filing units. Replaying the 30 c4 runs took 6 min 12 s before and 20 s after, with the same reasons chosen.

A measured choice, not a limit

When a prior has a band, the combined interval is the prior's band around the model's point and ignores the model's own interval. The walkthroughs measured it: on fomc-2024 the model's spanning intervals scored 827 against 489 for the band (198 with the yield floor), on cotpos 34.9 against 28.8, and on macrorev the band covered 7 of 12 against the model's 2.

Handled from the start

  • Documents dated after the cutoff, or undated, are dropped at load; none can reach a prompt, claim, reason or floor.
  • Ranking direction: points are the metric and ranks follow them, as the scorer reads them.
  • Corpus format: JSON documents with text, which is the only form the scorer accepts.
  • No code branches on unit ids or family slugs.

Glossary

The last date the documents may carry; the outcome resolves after it.

A forecast computed by code from an entity's history in the corpus: point, 90% band, the rows it used.

A prior whose point replaces the model's (revisions, growth from a copied level), shown to the model as a decided forecast.

A model request that copies a printed figure with a quote and forecasts nothing.

A cited span supporting one entity's forecast; false when off-entity, unsupported by its span, over 8,000 characters or content-free.

The fallback point and citation an entity takes when no reply gives one.
